# Pattern Atlas — local React learning workspace

React + Vite. A teaching-first field guide for Python coding assessments and future unseen problems.

- 21 pattern definitions and selection guides.
- 107 coding examples with constraints, complete Python code, block explanations, and explicit time/space derivations.
- 16 Python refresher examples and 14 language-pitfall notes.
- A visual playground for every coding/refresher example: 232 supplied input cases, each with a complete recorded source-line trace.
- Before/after arrays, dictionaries, linked structures and matrices; recursive call IDs; full event history; conceptual DP matrices where helpful.
- Every playground keeps the complete highlighted code, variable inspector and data visualisation together. A viewport-filling focus view, draggable panel docks, independent scrolling, optional line following and play/pause keep the visual stage clear.
- 25 SQL examples with schemas, sample rows, expected output, complete SQLite/PostgreSQL queries, explanation stages and query-plan reasoning.
- A focused study route, future-readiness self-checks, recognition questions, bookmarks and manually marked learning progress.

Code is reference material for your IDE. There are no live Python/SQL editors, execution runtimes, mock-assessment screens, or mistake logs.

## Run locally

Requirements: Node.js 20.19+ or 22.12+ (including Node 24), npm. Python 3 is needed only to regenerate/verify learning content.

```bash
cd /Users/mehmooa7/porfolio-development/pattern-atlas-react
npm install
npm run dev
```

Open **http://127.0.0.1:5178/#assessment**. No account, backend, API key, or cloud service is required. Google Fonts are optional; system fonts are fallbacks.

```bash
npm run build             # production files in dist/
npm run preview           # preview the production build
npm test                  # content/mapper/plan checks
npm run test:examples     # Python, SQL, traces and independent optimisation checks
npm run content:generate  # regenerate all content and recorded traces
```

The predev/prebuild step copies the canonical content and node helper file into public/. Vite then serves/packages the static learning data. It does not execute learner code. After regenerating content while a dev server is already running, run `node scripts/prepare-content.mjs`, then reload the page.

## Teaching content

- `src/data/patterns.json`: canonical method/example content.
- `src/data/python-drills.json`: Python worked examples.
- `src/data/sql-lessons.json`: SQL samples, reference queries and expected tables.
- `src/data/study-plan.json`: the 400-minute core route and Python pitfalls.
- `public/traces/`: every recorded sample execution. These are generated by CPython using source-line events.
- `src/components/WorkedExample.jsx`: whole code, explanation, complexity and embedded playground.
- `src/components/TraceViewer.jsx`: shared playground workspace, code/variable docks, focus mode, playback, before/after state, full history, input-case selection and matrix rendering.
- `src/components/AllPlaygrounds.jsx`: global selector for all 123 coding/refresher examples.
- `src/components/SQLExamples.jsx`: query examples and logical intermediate/output tables.
- `src/lib/engine.js`: deterministic candidate mapper and recognition questions.
- `LOVABLE_PROMPT.md`: product specification. `AGENTS.md` is what Lovable reads when editing.

A trace snapshot is taken **before** its displayed source line. The next event in the same call supplies its after state. Recursive calls get separate IDs. A built-in operation is represented by its before/after data rather than expanded C internals. Tuple assignments show their simultaneous changes together. Conceptual DP matrices are explicitly labelled separately from the storage used by the efficient code.

In any lesson or the global playground, choose **Focus playground** to keep code, variables and the visual stage inside the viewport. Drag a panel header to the other dock, use its arrow button, or press Enter on the header to swap panels. The docks reserve their own space and cannot cover the data. **Reset panels** restores the layout. On smaller screens the panels sit below the stage. All code lines and local values remain available through independent scrolling; long code lines wrap. Switch off **Follow line** to browse code without playback repositioning it. Click a variable to inspect its full before/after visual state. Previous/Next and slider movements pause playback; Play restarts after the final event. Escape exits focus and returns to the lesson.

The efficient implementations explain assumptions and tradeoffs. Randomised quickselect has expected linear selection with quadratic worst-case time; heap alternatives have predictable bounds and preserve input. Output space is distinguished from auxiliary space. Large-integer arithmetic bounds count arithmetic operations where stated.

All 25 SQLite outputs are verified against independently specified tables. PostgreSQL references are syntax examples and were not executed against a PostgreSQL server. Their physical performance depends on data, indexes, statistics and plans; SQL does not have a universal time/space bound from text alone.

## Learning journey

Tonight’s route is 6 hours 40 minutes of focused work, plus breaks/sleep, with an optional 45-minute SQL block. The actual Equip assessment duration/questions/difficulty are unknown; SQL is not confirmed as an assessment topic. These exercises are independent preparation examples.

For future unseen questions: understand the contract and invariant → predict each state → rebuild in your IDE → change a constraint → mix problems without tags → justify correctness and complexity → revisit weak methods. Reading alone does not establish mastery. The collection covers common foundations; advanced range structures, specialised DP and deeper graph algorithms are future extension topics.

Manual method/bookmark state uses `pattern-atlas-v1`; study/readiness checkboxes use `pattern-atlas-journey-v1`. Progress stays on this browser/origin, without device synchronisation. Your problem-mapper text is processed locally and held in memory. No salary, personal employment history or recruiter contact data is embedded in the app.

## Lovable

Import this repository as the existing Vite app. `AGENTS.md` is the instruction file Lovable reads; `CLAUDE.md` points at it. Project facts are in `.lovable-agent/context.md`. `LOVABLE_PROMPT.md` is the product specification, not a request to rebuild.

Keep `public/favicon.svg` and the icon link in `index.html`. Copy source excluding `node_modules/`, `dist/`, and `__pycache__/`, then run `npm install` and `npm run dev`. The source has no hosting identity or credentials.
